# CMSForum 工程化模块化开发文档

> **基于 MKSINE 底座（Laravel + Filament）的模块化 CMS / Forum / 商业扩展平台**
>
> 版本：v1.1（2026-08-25）
> 状态：待评审
>
> 本版变更（相对 v1.0）：
> - ADR-001 反转：**前台用户界面 = Inertia + Vue3 + TypeScript + Tailwind + shadcn-vue**；后台 = Filament 5（Livewire/Blade 底层）。前后台独立 UI，互不侵入。
> - 侧边栏卡片系统：**CMS 与 Forum 各自独立实现**（各自表、各自类型、各自后台管理页），不建共享模块。
> - 技术栈锁定 **Filament 5.x**。
> - Payment：**先交付底座**（统一网关接口 + Mock 渠道），真实渠道（微信/支付宝/Stripe）后续逐个添加。
> - InviteCode：**注册是否强制邀请码 = 后台管理设置**，默认开放，可一键强制。
> - Notification：**先交付底座**（事件订阅 + 站内信渠道），邮件/短信等渠道后续按驱动添加。
> - 安全约束新增：解析不可信 XML（如支付回调）前拒绝 DOCTYPE/ENTITY、不启用外部实体。

## 0. 阅读指引与术语

| 术语 | 含义 |
| --- | --- |
| 底座（MKSINE） | `miran/mksine` 包，提供插件、主题、媒体、菜单、设置、Hook/Filter/短码、Filament 后台等基础能力，**只扩展不改源码** |

| 后台（Admin） | Filament 5 面板（Livewire/Blade 底层），由底座 `MksinePlugin` 提供，模块通过 Filament 资源/页面扩展 |

## 1. 项目定位与目标

> **做一个自己的 WordPress + Flarum + AI 社区平台**：Laravel 版一体化平台，CMS 与 Forum 代码层完全解耦，可单独部署、可组合、可商业化。

### 1.1 第一性目标

1. **底座复用**：插件、媒体、菜单、设置、Hook/Filter/短码、Filament 后台全部建立在 MKSINE 之上，不重写。
2. **前台自由**：前台用户界面独立实现为 Inertia + Vue3 + shadcn-vue，不受底座 Blade/Livewire 前台机制限制。
3. **模块独立**：CMS、Forum 各自是独立模块，删掉任何一个，另一个照常运行。
4. **共用后端、独立 UI**：前后台共用 Laravel 后端与数据库；前台 UI、后台 UI 各归各。
5. **商业扩展**：支付（底座先行）、邀请码、会员、AI 作为可插拔模块按需启用。

### 1.2 本次需求的模块范围

| 模块 | 需求来源 | 说明 |
| --- | --- | --- |
| CMS | 本次核心 | 两栏布局、文章多形态展示（卡片网格/列表式等）、侧边栏卡片（独立实现）、作者中心、后台卡片管理 |
| Forum | 本次核心 | 两栏布局、帖子列表式、侧边栏卡片（独立实现）、用户中心、后台卡片管理、用户数据/注册数据短码 |
| Payment | 本次核心（底座优先） | 统一支付网关接口 + Mock 渠道先交付；微信/支付宝/Stripe 渠道后续逐个添加 |
| InviteCode | 本次核心 | 邀请码获取（购买 / 货币按比例兑换）、生成、使用、绑定；注册是否强制 = 管理设置 |
| Economy | **必须补充** | 金币/银币/铜币（名称可自定义）货币内核，邀请码兑换与充值的地基 |
| Quest | **必须补充** | 签到 / 发布文章帖子等获取货币的规则模块 |
| User | **必须补充** | 前台用户中心/作者中心数据与组件、资料扩展、注册流程（含邀请码字段位） |
| Notification | **必须补充** | 通知底座（事件订阅 + 站内信渠道），邮件/短信渠道后续添加 |
| Comment | **必须补充** | 底座已有评论基础设施，模块化启用 |

> "还需要什么"的完整论证见 §5.4。

## 2. 技术栈决策（ADR）

### 2.1 ADR-001（v1.1 反转）：前台 = Inertia + Vue3 + shadcn-vue；后台 = Filament 5，互不侵入

**决策**：
- **前台（Storefront）**：Inertia.js（Laravel 官方 SPA 方案）+ Vue 3 + TypeScript + Tailwind CSS + **shadcn-vue** 组件体系。所有用户可见界面（首页、文章、论坛、用户中心、注册、邀请码、充值）都是 Inertia 页面 + Vue 组件。
- **后台（Admin）**：Filament 5（Livewire/Blade 底层）不动，MKSINE 后台能力全量复用。

**理由**：
1. 前后台本来就是两个独立 UI：Filament 后台由 `MksinePlugin` 提供，前台是我们自己的 Laravel 控制器返回 `Inertia::render()`。两者共享的是 Laravel 后端与数据库，不是模板栈，**互不冲突**。
2. MKSINE 的 Blade/Livewire 前台机制（`FrontendResolver`、Livewire 前端组件、`theme_view()`）**不属于必须依赖**：前台只保留对 MKSINE 数据模型、设置、媒体、短码（服务端渲染）、插件后台能力的复用；前台组件层由我们实现（见 §3.2 的"替换清单"）。
3. shadcn-vue 直接满足"shadcn/ui 风格"诉求，Vue 生态满足复杂交互。
4. 后台继续用 Filament 意味着：插件自动发现、资源/页面/设置 Tab 扩展、媒体选择器、权限（Shield）全部零成本复用。

**代价**：需要自建"前端主题机制"与"动态组件挂载"（见 §8、§9）；MKSINE 自带的前台 Livewire 组件（Home/PostList 等）不用于本项目前台。

### 2.2 ADR-002：后台锁定 Filament 5.x

MKSINE `composer.json` 声明 `filament/filament: ^4.0|^5.0`。本项目锁定 **Filament 5.x**（当前稳定线），后台代码按 5.x 编写。升级窗口：底座支持 5 才选 5，避免长期停在大版本边界。

### 2.3 ADR-003（v1.2 修订，原"各自实现"已废弃）：Sidebar 升级为系统级引擎

> 演进记录：v1.1 曾按用户要求让 CMS/Forum 各自实现卡片系统；实施后发现每模块重复建表/后台页/渲染器，
> 且用户明确提出"主题/插件要能注入 sidebar、未来产品也要可控"，故升级为系统级引擎。

**决策**：Sidebar 卡片系统放 **Core 层**（`app/Core/Sidebar`），作为与 Hook/菜单同级的基础设施：

- **Core 引擎**：区域注册表 + 卡片类型注册表 + `sidebar_cards` 实例表 + 后台统一管理页 + 前端通用渲染器。
- **内置类型**（系统自带，任何区域可用）：`image_link` 图片超链接、`text_link` 文本超链接（按钮可选）、`html` 广告代码（HTML/JS，仅超管可配）。
- **模块只声明区域**：CMS 在 `activate()` 注册 `cms.sidebar`，Forum 注册 `forum.sidebar`，未来任意产品注册自己的区域；模块特色卡（签到/分类/最新文章等）由模块向引擎**注册类型**。
- **插件可注入**：第三方插件注册新 CardType 即出现在所有区域的"新建卡片"下拉。
- **主题可覆盖**：主题目录同名组件覆盖默认卡片/页面渲染（见 §8）。

### 2.3.1 ADR-010：主题覆盖前端界面的机制

三层同名覆盖，主题文件优先于模块默认文件（由 `resolve.ts` 的 glob 优先级保证）：

| 层 | 主题位置 | 覆盖范围 |
| --- | --- | --- |
| 页面 | `themes/{id}/vue/Pages/**` | 整个 Inertia 页面 |
| 组件 | `themes/{id}/vue/components/**`（含 `cms/*` `sidebar/*` 卡片） | 布局与卡片外观 |
| 样式 | `themes/{id}/css/tokens.css` | shadcn 设计令牌（配色/圆角/字体） |

主题切换仍走底座设置（active_theme），前台共享 props 下发当前主题标识。

### 2.4 ADR-004：支付先底座、后渠道

第一版交付 **统一网关底座**：
- `PaymentGatewayContract`（统一接口）、`ChannelManager`（渠道注册）、`payments` 订单表、回调签名校验、幂等、主动查询、退款接口。
- 内置 `MockChannel`（本地联调）。微信、支付宝、Stripe 作为**渠道增量**后续逐个添加（每个渠道一个实现类 + 后台配置启用），提供"渠道开发指南"（§13.5）保证新渠道接入不改动底座。

### 2.5 ADR-005：注册是否强制邀请码 = 后台管理设置

默认 **不强制**（开放注册）；后台可切换"必须填写邀请码才能注册"，并可配置提示文案。见 §14.4。

### 2.6 ADR-006：通知先底座、后渠道

第一版交付**通知底座**：事件订阅器、`notifications` 表（站内信）、`NotificationChannelContract` 渠道接口、后台渠道管理（启用/禁用/配置）。第一版内置 **站内信渠道**；邮件（SMTP）、短信等渠道后续按驱动添加。

### 2.7 ADR-007：跨模块不建外键，只存 ID + 事件清理

模块表不建跨模块外键（可单独部署）；引用他模块 ID 只存 ID，逻辑校验；跨模块删除走事件通知清理。

## 3. MKSINE 底座能力盘点（复用 / 替换 / 新建）

### 3.1 直接复用（后台与数据层，零成本）

| 能力 | 用途 |
| --- | --- |
| 插件系统（PluginInterface/PluginManager/Registry） | 模块载体：安装/启用/停用/卸载、迁移、自动发现 Filament 组件 |
| Filament 面板（MksinePlugin） | 后台主体：SPA、Shield 权限、导航分组、Dashboard |
| 媒体库（Media/MediaAttachment/MediaPicker） | 后台选图、卡片图片、文章封面 |
| 菜单系统（Menu/MenuItem/MenuLocation） | 后台配置菜单，前台通过共享数据获取 |
| 设置系统（Setting/mks_setting/SettingsTabManager） | 站点设置、模块设置 Tab |
| Hook/Filter（Hooks::*） | 事件监听、表单/表格扩展、内容过滤器 |
| 短码引擎（ShortcodeRegistry/Processor/ContentRenderer） | 服务端渲染短码（前台 v-html 输出） |
| 内容数据（Post/Category/Page/Comment/MediaAttachment） | 文章/分类/评论数据模型直接复用 |
| 翻译管理、ZIP 升级、后台终端、SmartMigration | 运维能力 |

### 3.2 替换 / 不适用的（前台自建层）

| MKSINE 前台机制 | 状态 | 本项目替代 |
| --- | --- | --- |
| `FrontendResolver` + Livewire 前端组件（Home/PostList/PostShow/CategoryShow/PageShow/AuthorShow/PostComments） | **不使用** | 模块 Laravel 控制器返回 `Inertia::render()`（§4.4） |
| Blade 主题视图解析（`theme_view()`/`theme_layout()`/`theme_register_override`） | **不使用** | 前端主题机制：Vue 组件集 + 组件覆盖注册表（§8） |
| `theme_enqueue_style/script` + `@themeAssets` | **不使用** | Vite 构建 + 前端按需 import |
| `Hooks::addLivewireShortcode`（Livewire 短码挂载） | **不使用** | 服务端短码渲染为 HTML / 前端组件挂载占位（§9） |

### 3.3 需要新建的前台基础设施

1. **Inertia 应用骨架**：入口、路由解析、共享数据、布局（§4.4、§4.5）。
2. **前端主题机制**：主题 = Vue 组件集 + theme.json；后台切换主题复用底座 `Theme` 表/设置（§8）。
3. **shadcn-vue 组件库**：`resources/js/components/ui/*`，前后台之外的前台统一 UI 基座。
4. **短码动态组件挂载**：`data-vue-mount` 占位 + Vue 挂载指令（§9）。
5. **SSRF/XML 安全基础设施**：`SafeHttpClient` + `SafeXmlParser`（§17）。

### 4.4 前台 Inertia 集成要点

1. **路由**：模块 `routes/web.php` 注册控制器，返回 `Inertia::render('CMS/ArticleIndex', props)`。模块路由由插件系统加载；**与底座 FrontendResolver 默认路径错开**（如 `/articles`、`/forum`、`/users`），若需占用 `/` 首页，在应用层注册覆盖。
2. **组件解析**：`resources/js/resolve.ts` 用 `import.meta.glob` 合并应用页、模块页、主题页：

```ts
// resolve.ts
export const pages = import.meta.glob([
  '../pages/**/*.vue',
  '../../modules/*/resources/js/Pages/**/*.vue',
  '../../themes/*/vue/Pages/**/*.vue',   // 主题可覆盖同名页面组件（优先级见 §8）
])
```

3. **共享数据**（`HandleInertiaRequests`）：`auth.user`、站点设置（`mks_setting` 白名单）、`theme`（active_theme + 主题组件映射）、通知未读数、货币名称配置等。

### 4.5 后台与前台的关系

- 后台 = 底座 `MksinePlugin` 面板 + 模块 `Filament/` 资源（自动发现）。模块新增后台能力**零配置**出现。
- 前后台共用：Laravel 认证（同一 `users`）、媒体、设置、数据模型。前台登录态与后台一致（同 session）。

## 5. 模块清单、依赖矩阵与"还需要什么"

### 5.1 依赖矩阵（↓ 依赖 →）

### 5.2 模块职责边界

| 模块 | 职责 | 禁止职责 |
| --- | --- | --- |
| User | 前台用户中心/作者中心（数据 + Vue 组件）、资料扩展、注册流程（含邀请码字段位） | 不碰钱包与货币 |
| Economy | 货币定义（可配置名称）、钱包、流水、credit/debit 原子操作 | 不定义"赚货币"规则 |
| Quest | 签到、发布内容等**规则** → 监听内容事件 → 调 Economy credit | 不感知支付与邀请码 |
| CMS | 文章/分类/标签、多形态展示、CMS 侧边栏卡片、作者中心入口 | 不直接引用 Economy/Payment |
| Forum | 版块/帖子/回复/点赞/收藏、帖子列表、Forum 侧边栏卡片、用户数据短码 | 不直接引用 Economy/Payment |
| Payment | 统一网关接口、订单、回调、幂等、渠道注册；发 `payment.succeeded` 事件 | 不决定钱变成什么 |
| InviteCode | 邀请码生成/校验/兑换/使用/绑定；监听 `payment.succeeded` 与 Economy 扣减 | 不自己创建支付渠道 |
| Notification | 事件订阅 → 渠道分发（站内信底座，邮件/短信后续） | 不定义业务事件 |
| Comment | 底座多态评论 + 前台 Vue 组件 + 后台审核 | 不复刻评论存储 |

### 5.3 事件契约（模块间通信"公共字典"）

底座已有：`PostCreated/PostCreating/PostUpdated/PostUpdating`、`Category*`。

本项目新增：

| 事件 | 来源模块 | 监听方示例 |
| --- | --- | --- |
| `cms.article.published` | CMS | Quest(奖励)、Notification、AI(摘要)、Search |
| `forum.topic.created` / `forum.reply.created` | Forum | Quest(奖励)、Notification、@提及 |
| `user.registered` | User | InviteCode(核销+绑定)、Notification、Quest(新手奖励) |
| `economy.wallet.credited` / `economy.wallet.debited` | Economy | InviteCode(余额变动)、Notification |
| `quest.daily_checkin` / `quest.completed` | Quest | Economy(发钱)、Notification |
| `payment.succeeded` / `payment.failed` | Payment | Economy(充值)、InviteCode(购买发货)、Notification |
| `invitecode.redeemed` / `invitecode.issued` | InviteCode | Notification(邀请人)、Quest(邀请奖励) |
| `notification.sent` | Notification | 审计 |

规则：事件只携带领域对象 ID + 必要载荷；监听方通过 Contract 按 ID 取数；事件定义放**发布方**模块。

### 5.4 评审结论：还需要什么

在用户点名的 CMS/Forum/Payment/InviteCode 之外，**必须补**：

1. **Economy 货币内核（最高优先）**——邀请码"金币银币铜币按比例兑换"、支付"充值"、签到/发帖"奖励"共同落在 `wallets + wallet_ledger` 上；货币名称可配置。
2. **Quest 签到任务**——"签到、发布文章、发帖获取货币"是明确需求，是货币的主要来源规则。
3. **User 前台用户中心**——侧边栏"作者中心/用户中心"卡片与页面的数据源；`user_profiles` 扩展表。
4. **Notification 通知底座**——注册、邀请码、支付、回复都要通知；先站内信，渠道驱动化。
5. **Comment 启用**——底座已有完整多态评论，薄模块接入即可。
6. **Tags**——底座**没有**标签表，CMS 需要新增 `tags + post_tag`。

**建议补（Phase 5+）**：SEO 增强、Moderation（注册审核/举报/敏感词）、AI、Search（Meilisearch）、Analytics、私信、关注关系。

**工程必补（机制，非模块）**：
7. **前端主题机制（§8）**——Inertia 前台下"主题切换"的实现方式。
8. **短码动态组件挂载（§9）**——服务端 HTML + 前端组件挂载占位。
9. **契约层 Contracts（§16）**——`ContentContract` 等，CMS/Forum 解耦关键。
10. **安全基础设施（§17）**——`SafeHttpClient`（SSRF）、`SafeXmlParser`（XML 实体攻击），Mimosa 验收条件。

## 6. 模块化插件开发规范（基于底座 PluginInterface）

### 6.1 模块主类（CMS 示例）

```php
<?php
declare(strict_types=1);

namespace Modules\CMS;

use Miran\Mksine\Core\Plugins\Contracts\PluginInterface;
use Miran\Mksine\Core\Hooks\Hooks;

class CMSPlugin implements PluginInterface
{
    public function id(): string { return 'cms'; }

    public function install(): void
    {
        // 迁移由 plugin:migrate 执行；此处写初始数据（默认布局、默认卡片区域）
    }

    public function activate(): void
    {
        // 依赖自校验（§6.2）
        foreach (['user'] as $required) {
            if (! module_enabled($required)) {
                throw new \RuntimeException("模块 cms 依赖 {$required}，请先安装并启用。");
            }
        }

        // 注册短码（服务端渲染；带目录）
        Hooks::addShortcode('post_list', PostListShortcode::class, catalog: new ShortcodeCatalogEntry(...));

        // ★ 注册 CMS 独立卡片类型（§7）
        CmsCardRegistry::registerType(new ImageLinkCard());
        CmsCardRegistry::registerType(new TextLinkCard());
        CmsCardRegistry::registerType(new HtmlCard());
        CmsCardRegistry::registerType(new UserCenterCard());

        // 注册前端布局（§8）
        LayoutRegistry::register('grid', ...);     // 卡片网格
        LayoutRegistry::register('list', ...);     // 列表式
        LayoutRegistry::register('magazine', ...); // 杂志混合
    }

    public function deactivate(): void { /* 移除对外暴露；数据保留 */ }
    public function uninstall(bool $deleteData = false): void
    { if ($deleteData) { /* 删除模块表 */ } }
    public function boot(): void { /* 路由已在 routes/web.php 由插件系统加载 */ }

    public function migrationsPath(): ?string { return __DIR__.'/../database/migrations'; }
    public function configPath(): ?string { return __DIR__.'/../config'; }
    public function viewsPath(): ?string { return __DIR__.'/../resources/views'; }
    public function webRoutesPath(): ?string { return __DIR__.'/../routes/web.php'; }
    public function apiRoutesPath(): ?string { return null; }
    public function translationsPath(): ?string { return __DIR__.'/../resources/lang'; }
    public function filamentResourcesPath(): ?string { return is_dir($p=__DIR__.'/../Filament/Resources')?$p:null; }
    public function filamentPagesPath(): ?string { return is_dir($p=__DIR__.'/../Filament/Pages')?$p:null; }
    public function filamentWidgetsPath(): ?string { return is_dir($p=__DIR__.'/../Filament/Widgets')?$p:null; }
    public function namespace(): ?string { return 'Modules\\CMS'; }
}
```

### 6.2 依赖声明与自校验

底座 `PluginLifecycle::install/activate` 只校验 mksine 版本，不校验模块间依赖、也不触发生命周期事件。采用**模块自校验**（不改底座）：在 `activate()` 开头检查 `requires` 中模块是否启用，不满足抛异常——底座会捕获异常、回滚 `mks_plugins` 记录并终止。

应用层 helper（`app/Support/helpers.php`）：

```php
function module_enabled(string $moduleId): bool
{
    try {
        $manager = app(\Miran\Mksine\Core\Plugins\PluginManager::class);
        $manager->isInitialized() || $manager->initialize();
        return $manager->getRegistry()->isActive($moduleId);
    } catch (\Throwable) {
        return false;
    }
}
```

### 6.3 启用/停用可见行为约定

- 停用模块：前台路由 404，后台导航分组消失，**数据表保留**。
- 卸载（deleteData=true）：删表、清理媒体附件（先归档）。
- 版本升级：底座 ZIP Updater + SmartMigration；模块发布用 `mks:release-archive`。

## 7. 核心机制一：侧边栏卡片系统（CMS / Forum 各自独立实现）

> 用户要求：CMS 与 Forum 的侧边栏卡片**分开、各模块重新实现**。因此本系统是"规范 + 两套独立实现"，不存在共享卡片模块。

### 7.1 统一规范（Core 可选接口，仅约束写法）

`app/Core/Cards/CardTypeContract.php`（CMS/Forum 各自实现，互不依赖）：

```php
interface CardTypeContract
{
    public function typeKey(): string;        // 'image_link' | 'text_link' | 'html' | 'user_center' | ...
    public function label(): string;
    public function schema(): array;          // Filament Schema（后台表单）
    public function render(Card $card): string;  // 服务端兜底渲染（SSR/邮件等）
    public function vueComponent(): string;   // 前端组件 key（如 'cms/cards/image-link'）
    public function authorize(User $user): bool;
}
```

### 7.2 CMS 卡片系统（模块内实现）

- 表：`cms_cards`（`id | area_key | type | title | sort | enabled | data(json) | created_at`）；区域常量 `cms.sidebar`。
- 类型注册表：`Modules\CMS\Cards\CmsCardRegistry`（singleton），`activate()` 时注册。
- 后台管理页：`Filament/Resources/CmsCardResource`——列表（类型/标题/排序/启用）、表单按所选类型动态加载 Schema。即"后台管理卡片化"。
- 渲染：CMS 前台页面（Inertia）把 `cms.sidebar` 区域的卡片实例（type + data）放进 Inertia props，Vue 侧 `CmsSidebar.vue` 按 `type.vueComponent` 动态渲染对应卡片组件；服务端 `render()` 作为无 JS 兜底。

### 7.3 Forum 卡片系统（模块内实现）

- 表：`forum_cards`（结构同 cms_cards）；区域常量 `forum.sidebar`。
- 类型注册表：`Modules\Forum\Cards\ForumCardRegistry`。
- 后台管理页：`Filament/Resources/ForumCardResource`（独立页面）。
- 渲染：Forum 前台 `ForumSidebar.vue` 按类型渲染 `forum_cards` 实例。

### 7.4 内置卡片类型（两套实现各自提供，第一版交付）

| type | 后台表单 | 前端渲染 |
| --- | --- | --- |
| `image_link` 图片超链接 | 图片(MediaPicker)/URL/新窗口/alt | `<a><img loading="lazy"></a>` |
| `text_link` 文本超链接 | 标题/正文/URL/按钮文案 | 文本卡片 + 链接 |
| `html` 代码卡片 | 代码编辑器(HTML/JS/CSS) | `v-html`（**权限 + 清洗**，见 §17） |
| `user_center` 用户中心 | 标题/是否显示当前用户 | 登录→当前用户资料+钱包+快捷入口；未登录→登录/注册按钮 |
| `author_center` 作者中心（内容页） | 标题 | 当前文章/帖子作者资料 + TA 的内容数 |
| `stat` 统计卡片 | 统计项多选 | 内容数/回复数等 |

> **作者中心 / 用户中心 = `user_center` / `author_center` 类型**。两套实现都基于 User 模块提供的"用户中心数据服务 + 共享 Vue 组件（UserCenterPanel）"编写各自的卡片类型；**卡片系统本身（表、注册表、后台页、区域渲染）彼此独立**。

### 7.5 后台管理页（两套独立，形态一致）

- `CmsCardResource` / `ForumCardResource`：按区域 Tab 分组；类型筛选；表单按类型动态加载；`html` 类型创建权限默认 super_admin（§17）。

## 8. 核心机制二：前端主题机制 + 内容展示布局（Inertia 前台）

### 8.1 前端主题 = Vue 组件集

- 主题目录 `themes/{id}/`（或 `resources/js/themes/{id}/`），含 `theme.json`：

```json
{
  "name": "Default",
  "version": "1.0.0",
  "author": "CMSForum Team",
  "screenshot": "screenshot.png",
  "components": {
    "layout": "AppLayout.vue",
    "cms.post-grid": "PostGrid.vue",
    "cms.post-list": "PostList.vue",
    "cms.single": "ArticleShow.vue",
    "forum.topic-list": "TopicList.vue",
    "card.image_link": "ImageLinkCard.vue"
  }
}
```

- `components` 把"组件 key"映射到主题内的 Vue 文件；未声明的 key 回退模块默认组件。
- 主题切换：后台设置 `active_theme`（复用底座 `Theme` 表与后台主题管理页）；`HandleInertiaRequests` 把 `theme`（identifier + 组件映射 + 资源 URL）放入共享 props；前端 `ThemeProvider.vue` 用 `import.meta.glob` 注册全部主题组件并按映射解析（`vue:dynamic` + 回退默认）。
- 第一版交付主题：`default`（shadcn-vue 风格，两栏布局）；`modern` 作为第二主题示例。

### 8.2 两栏布局（前台默认主题约定）

- `AppLayout.vue`：`<header>`（站点导航，数据来自底座菜单）→ `<main class="grid lg:grid-cols-12">`：
  - 主栏 `lg:col-span-8`：页面组件（文章网格/列表、帖子列表、详情）
  - 侧边栏 `lg:col-span-4`：`CmsSidebar.vue` / `ForumSidebar.vue`（渲染各自卡片区）
- `AppLayout.vue` 本身也是主题组件（`components.layout`），模块不持有布局，主题持有。

### 8.3 内容展示布局系统（CMS）

- 布局 = 文章集合的一种渲染形态，注册 key + 前端组件：

```php
LayoutRegistry::register('grid', [
    'label' => '卡片网格', 'component' => 'cms.post-grid', 'defaults' => ['show_excerpt' => true],
]);
LayoutRegistry::register('list', ['label' => '列表式', 'component' => 'cms.post-list', ...]);
LayoutRegistry::register('magazine', ['label' => '杂志', 'component' => 'cms.post-magazine', ...]);
```

- 站点默认布局存 `cms_settings('default_post_layout')`；URL 支持 `?layout=list` 切换（可选）。
- 主题覆盖：主题 `theme.json` 声明同名 `cms.post-grid` 即覆盖默认组件——即"主题可换外观、模块提供功能"。
- 模块默认组件：`modules/CMS/resources/js/Components/PostGrid.vue`、`PostList.vue`、`PostMagazine.vue`（shadcn-vue 卡片/列表样式）。

## 10. 核心机制四：Economy 货币内核（新模块，最高优先）

> 邀请码兑换、充值、签到奖励的共同地基。货币名称（金币/银币/铜币或自定义）与数量完全可配置。

### 10.1 配置（config/economy.php）

```php
return [
    'currencies' => [
        ['key' => 'gold',   'name' => '金币', 'unit' => 1],
        ['key' => 'silver', 'name' => '银币', 'unit' => 0.1],
        ['key' => 'copper', 'name' => '铜币', 'unit' => 0.01],
        // 名称可后台改：economy_currency_configs 表覆盖
    ],
];
```

### 10.2 数据表

```sql
wallets
  id | user_id(uniq) | currency | balance(decimal 18,6) | updated_at

wallet_ledger
  id | wallet_id | currency | type(credit|debit) | amount | balance_after
  | ref_type | ref_id | remark | created_at
  -- 幂等唯一: (wallet_id, ref_type, ref_id, type)

economy_currency_configs
  id | key | name | unit | enabled   -- 后台可编辑名称/汇率
```

### 10.3 WalletService（原子 + 幂等）

```php
final class WalletService
{
    public function apply(User $user, string $currency, string $type, string|float $amount,
                          string $refType, int|string $refId, string $remark): LedgerEntry;
    public function transfer(User $from, User $to, string $currency, float $amount, string $remark): void;
    public function balance(User $user, string $currency): float;
}
```

- 行锁（`lockForUpdate`）→ 余额校验 → 更新 → 写流水 → 发 `economy.wallet.credited/debited`。`(ref_type, ref_id)` 幂等：重复通知不重复入账。
- 对外 API：`Economy::credit($user, 'gold', 100, 'quest:checkin', $userId, '签到奖励')`、`Economy::debit(...)`、`Economy::balance(...)`。

## 13. Payment 支付模块（底座优先，渠道后续添加）

### 13.1 统一网关接口（第一版交付）

```php
// Modules\Payment\Contracts\PaymentGatewayContract
interface PaymentGatewayContract
{
    public function key(): string;                              // 'mock' | 'wechat' | 'alipay' | 'stripe' | ...
    public function createPayment(PaymentRequest $r): PaymentRedirect; // 跳转/二维码/客户端参数
    public function queryOrder(string $orderNo): PaymentStatus;
    public function verifyWebhook(array $payload, array $headers): PaymentEvent; // 签名校验
    public function refund(string $orderNo, float $amount): void;
    public function enabled(): bool;
}
```

- `ChannelManager`（singleton）注册渠道；`config/payment.php` 声明启用渠道；渠道实现类只操作 `payments` 表 + 自身配置，**不碰业务表**。
- 第一版渠道：`MockChannel`（本地联调，模拟成功/失败）。**微信/支付宝/Stripe 后续逐个添加**（§13.5 渠道开发指南）。

### 13.2 数据表

```sql
payment_channels
  id | key | name | enabled | config(json, 加密存储) | sort

payments
  id | order_no(uniq) | user_id | channel | amount(decimal) | currency
  | subject | status(pending|paid|failed|refunded|closed) | paid_at
  | provider_trade_no | raw_notify(json) | created_at

payment_events      -- 回调幂等
  id | payment_id | event | payload(json) | processed_at   -- 唯一: (payment_id, event)
```

### 13.3 回调安全与幂等（工程红线）

1. **签名校验**：每渠道实现 `verifyWebhook`；失败直接 4xx，不落库。
2. **金额一致性**：回调金额必须等于订单金额，不一致标记 fraud 并告警。
3. **幂等**：`(payment_id, event)` 唯一约束，重复通知不重复处理。
4. **只信服务端**：状态以主动查询（`queryOrder`）为准。
5. **SSRF 约束**：所有对外请求走 `SafeHttpClient`（§17.1）。
6. **XML 安全**（微信支付回调为 XML，Mimosa 验收条件）：解析不可信 XML 前拒绝 DOCTYPE/ENTITY、不启用外部实体（§17.2）。

### 13.4 与业务解耦（事件驱动）

- 支付成功 → `payment.succeeded(Payment $payment, string $bizType, int $bizId)`；支付模块**不知道业务**：
  - InviteCode 监听（biz_type=invite_purchase）→ 生成邀请码；
  - Economy 监听（biz_type=wallet_recharge）→ credit 入账（幂等）。
- `[wallet_recharge]` Vue 组件 → 选金额+渠道 → 下单 → 跳渠道 → 回调 → 事件 → 入账。

### 13.5 渠道开发指南（后续添加的标准步骤）

1. 实现 `PaymentGatewayContract`（key=wechat/alipay/stripe…）；
2. 实现 `verifyWebhook` 签名校验（微信：XML 解析走 `SafeXmlParser`；支付宝：RSA 验签；Stripe：Webhook 签名头）；
3. 在 `config/payment.php` 添加渠道配置段（appid/secret/merchant，后台加密录入）；
4. `ChannelManager::register(new WechatChannel())`（渠道提供方注册）；
5. 后台"支付渠道"页启用 + 配置；
6. 写渠道单测（Mock 服务端回调验签/幂等/退款）。

## 14. InviteCode 邀请码模块详细设计

### 14.1 数据模型

```sql
invite_code_products
  id | name | price_type(currency|payment) | currency | price_amount
  | payment_channel | payment_amount | quota_per_user | enabled

invite_codes
  id | owner_id | product_id(null) | code_hash(sha256) | code_prefix | status(unused|used|expired|revoked)
  | source(paid|redeem|grant) | currency | cost_amount | expires_at | used_by | used_at | created_at

invite_relations
  id | inviter_id | invitee_id | code_id | created_at
```

### 14.2 获取方式（需求落地）

| 方式 | 流程 |
| --- | --- |
| **购买邀请码** | 前台选商品 → Payment 下单（biz_type=invite_purchase）→ 回调 → `payment.succeeded` → 生成邀请码 → 通知 |
| **货币兑换** | `Economy::debit(currency, cost)`（幂等）→ 按汇率生成邀请码（后台可配 100 金币=1 码）→ `invitecode.issued` |
| **任务/签到获取货币** | Quest 奖励货币（不直接发码）→ 用户再用货币兑换 |

> 货币名称与兑换比例全部可配置，满足"金币银币铜币或自定义名称按比例转换成邀请码"。

### 14.3 生成与使用

- 短码：`{prefix}{8位随机}`（`random_bytes`）；**只存 `code_hash`**，展示一次。
- 长码（批量卡密）：`{prefix}{20位}`，管理员批量导出。
- 使用：`status=unused` 且未过期；`used_by`+`used_at` 原子更新（行锁 + 唯一约束防并发）。
- 事件：`invitecode.redeemed(inviter_id, invitee_id)` → Notification 通知邀请人 + Quest 邀请奖励。

### 14.4 注册集成与强制设置（管理设置）

- `RegisterForm.vue` 增加可选"邀请码"字段（未登录用户）。
- 后台设置（`InviteSettingsPage`）：
  - `invite.settings.required`（默认 **false** 开放注册；可开启**强制**）；
  - `invite.settings.required_message`（未填邀请码时的提示文案）；
  - 兑换汇率、码前缀、有效期、每人配额、批量生成。
- 注册成功 → `user.registered(user, invite_code?)` → InviteCode 监听：核销 + 写 `invite_relations`；强制模式下未填码 → 拒绝注册并提示。

### 14.5 后台

`InviteCodeProductResource`、`InviteCodeResource`（状态/来源/归属/使用人）、`InviteRelationResource`（关系树）、`InviteSettingsPage`（含强制开关与汇率）。批量生成：`php artisan invite:generate {n}` + 后台按钮导出。

## 16. 模块解耦与通信规范（工程红线）

### 16.1 依赖方向

```
Core / 契约层（CardTypeContract / ContentContract / Economy 门面）
        ▲
        │ 只依赖底座 + 契约
   CMS / Forum / Quest / Payment
        ▲
        │
  InviteCode / Notification（可依赖上述模块的公开契约与事件）
```

- **禁止**：CMS 里 `use Modules\Forum\Models\Topic`；模块间禁止互相 `new`、禁止直接跨模块读写表。
- 跨模块取数一律：公开 Contract（接口）+ 服务门面（可选）。

### 16.2 公开契约（ContentContract）

```php
interface ContentContract
{
    public function contentId(): int|string;
    public function contentTitle(): string;
    public function contentBody(): string;
    public function author(): User;              // 通过底座 MksUserInterface
    public function publishedAt(): ?Carbon;
    public function contentUrl(): string;
    public function contentType(): string;       // 'cms.article' | 'forum.topic'
}
```

- `Article implements ContentContract`、`Topic implements ContentContract`。
- Quest（奖励）、AI、Search 只依赖 `ContentContract`，不感知文章还是帖子。

### 16.3 通信三板斧（按优先级）

1. **事件（Event）**：状态变化通知（`user.registered`、`payment.succeeded`…）。发布方定义 + 数据，监听方 `Hooks::register`。
2. **Filter（数据管道）**：内容输出前加工（SEO、推荐），`Hooks::addFilter`。
3. **公开服务（Contract + 门面）**：命令式调用（`Economy::credit`），消费方只依赖接口。

### 16.4 可选依赖降级

- `activate()` 中监听事件前用 `module_enabled()` 探测（底座 `PluginRegistry::isActive`），未启用不注册监听（不报错）。
- 视图用 `optional()` 包裹 + `@if (module_enabled('payment'))`。
- 依赖校验：§6.2 自校验拦截（抛异常回滚）。

### 16.5 表命名与外键

- 模块表一律模块前缀（`cms_`/`forum_`/`economy_`/`invite_`/`payment_`…）。
- 跨模块不建外键；引用他模块 ID 只存 ID + 逻辑校验；跨模块删除走事件清理（软删除优先）。

## 17. 安全设计

| 领域 | 约束 |
| --- | --- |
| **SSRF（全项目）** | 服务端发起外部请求统一 `SafeHttpClient`：仅允许 `http/https`；请求前校验 host，拒绝 localhost/环回/私有/保留地址（127.0.0.0/8、::1、10/8、172.16/12、192.168/16、169.254/16、0.0.0.0）；DNS 解析后用解析出的 IP 二次校验再连接（防 DNS rebinding）；目标域名白名单（支付渠道、远程媒体源） |
| **XML 解析（不可信输入）** | 统一 `SafeXmlParser`：解析前**拒绝 DOCTYPE/ENTITY**（扫描输入或 libxml 禁用），**不启用外部实体**（`LIBXML_NONET` + 不设置 `LIBXML_NOENT`/`substituteEntities`）；微信支付回调等 XML 一律走它 |
| 支付回调 | 签名校验 → 金额一致性 → 幂等表 → 主动查询兜底（§13.3） |
| 钱包/兑换 | 行锁 + 流水 + `(ref_type, ref_id)` 幂等；兑换比率后台配置且变动留审计 |
| 邀请码 | 只存 hash；批量导出仅限超级管理员；`status` 原子流转防并发重复使用 |
| 代码卡片（html 类型） | `v-html` 输出前 HTMLPurifier 白名单（标签 + 内联样式白名单 + 剔除 `on*` 与 `javascript:` URL）；创建权限默认 super_admin；外链 JS 白名单 |
| 短码 | 正文 `v-html` 前统一清洗；短码参数 `htmlspecialchars` 转义；禁止短码执行任意 PHP |
| 上传 | 复用底座 media（类型白名单、文件名清洗、可开启扫描）；插件/主题 ZIP 安装走底座校验 |
| XSS | 富文本（CKEditor）输出前清洗；Vue 模板默认转义，仅白名单处 `v-html` |
| 权限 | 后台统一 Filament Shield 策略；`html` 卡片、邀请码导出、支付配置为高敏感权限，默认仅 super_admin |
| 审计 | Economy 流水、支付事件、邀请码流转、通知发送全留痕 |
