## 1. 项目概览

CMSForum 是一个**内容社区平台**：文章（Post）/ 分类 / 标签 / 评论 / 媒体库 / 菜单 / 单页 / 主题 由底层 CMS 内核提供；签到、任务奖励、虚拟货币钱包、商品商城、邀请码、加密货币付费阅读、广告位、性能优化中心等能力，则以**可插拔模块**的形式叠加在内核之上。

### 1.1 三层架构

| 层次 | 位置 | 职责 |
| --- | --- | --- |
| **内核层** | `vendor/miran/mksine` (v1.4.0) | CMS 底座：Post/Category/Media/Menu/Page/Setting 等模型、Filament 后台基础面板、插件管理器、钩子系统（Hooks）、短码系统、主题系统、Geo 数据 |
| **应用层** | `app/`、`routes/`、`resources/` | 站点级能力：Inertia 共享数据、系统级侧边栏引擎、站点设置、备份管理、插件打包器、GA / 性能仪表盘、广告与页脚后台资源、授权策略 |
| **模块层** | `modules/`（9 个插件） | 业务功能，可独立安装 / 启用 / 停用 / 卸载，各自携带迁移、路由、模型、Filament 资源、前端页面与测试 |

### 1.2 模块清单

| 模块 | 名称 | 核心能力 | 依赖 |
| --- | --- | --- | --- |
| `user` | 用户中心 | 注册（邮箱验证码 / 白名单）、用户资料、作者主页 | — |
| `cms` | 内容管理 | 固定链接、分类页、搜索、RSS、Sitemap、单页、轮播图、评论、创作中心 | `user` |
| `economy` | 货币内核 | 多币种钱包（金/银/铜）、流水账、幂等记账 | `user` |
| `quest` | 签到任务 | 每日签到、发布奖励，发放 economy 货币 | `user`、`economy` |
| `crypto-pay` | 加密支付 | 付费文章、统一支付网关（码支付/虎皮椒/PayPal/Xcash/Mock） | — |
| `shop` | 商品商城 | 商品、库存、订单、多种发货方式 | — |
| `invite` | 邀请码 | 管理员生成 / 金币购买 / 加密支付购买，注册核销 | — |
| `ads` | 广告管理 | 11 个投放位置，文本/图片/图文/卡片/HTML 五种形态 | — |
| `performance` | 性能优化 | 整页缓存、命中统计、Redis/OPcache/Octane/Horizon 探测 | — |

## 3. 快速开始

### 3.1 环境要求

- PHP >= 8.3，扩展：`pdo_sqlite` 或 `pdo_mysql`、`mbstring`、`openssl`、`fileinfo`、`zip`、`intl`（推荐）
- Composer 2.x
- Node.js >= 20（建议 22+）+ npm
- （可选）Redis、MySQL 8.x

### 3.2 安装

```bash
composer install
cp .env.example .env          # Windows: copy .env.example .env
php artisan key:generate
php artisan migrate --force   # 内核 + 应用迁移
npm install --ignore-scripts
npm run build                 # 或 npm run dev
```

`composer setup` 可一次性完成上述全部步骤。

### 3.3 初始化账号与演示数据

```bash
php artisan db:seed --class=AdminAccountSeeder   # 创建/重置 super_admin
php artisan db:seed --class=AuthorRoleSeeder     # 创建 author 角色
php artisan db:seed --class=CmsDemoSeeder        # 演示文章/分类
php artisan db:seed --class=CmsBannerSeeder      # 首页轮播图
php artisan db:seed --class=StaticPageSeeder     # 隐私/条款/关于
php artisan db:seed --class=NavigationSeeder     # 页眉页脚菜单
php artisan db:seed --class=FooterColumnsSeeder  # 页脚多列
```

管理员账号密码由 `.env` 提供：

```
ADMIN_DEFAULT_EMAIL=admin@cmsforum.test
ADMIN_DEFAULT_PASSWORD=<your-password>
```

> `AdminAccountSeeder` 每次运行都会把该账号密码**重置**为 `.env` 中的值并授予 `super_admin` 角色。未配置 `ADMIN_DEFAULT_PASSWORD` 时跳过并给出警告。

### 3.4 激活模块

模块必须先安装再启用，最后执行模块迁移：

```bash
php artisan mks-plugin:discover              # 扫描 modules/ 下的 plugin.php
php artisan mks-plugin:list                  # 查看状态
php artisan mks-plugin:install user          # 安装（执行 install() 钩子）
php artisan mks-plugin:activate user         # 启用（执行 activate()，含依赖自校验）
php artisan mks-plugin:migrate user          # 跑模块自身的 database/migrations
```

推荐顺序：`user` → `economy` → `quest` → `cms` → 其余模块。

> 模块的 `activate()` 内置依赖自校验，例如 `quest` 依赖 `user` + `economy`，缺失时直接抛 `RuntimeException` 并中止启用。

### 3.5 运行

```bash
# 开发：一条命令启动 server + queue + logs + vite
composer dev          # 等价于 php artisan dev

# 或分别启动
php artisan serve
npm run dev

# 队列与定时任务
php artisan queue:work --tries=3
php artisan schedule:work
```

`schedule:work` 必须常驻——定时发布依赖它（见 [13.3](#133-定时任务)）。

### 3.6 测试

```bash
php artisan test                     # 或 composer test
php artisan test --filter=WalletServiceTest
```

- 应用测试位于 `tests/Unit`、`tests/Feature`。
- 模块测试位于 `modules/<id>/tests/`，统一继承 `Modules\Tests\ModuleTestCase`（`modules/Tests/ModuleTestCase.php`）。
- **注意**：`phpunit.xml` 中配置测试库为 **MySQL `cmsforum_test`**，而 `.env.example` 默认使用 **SQLite**。跑模块测试前需准备 MySQL 库并配置连接，否则测试会连接失败。

## 5. 架构设计

### 5.1 请求处理管线

```
HTTP 请求
  └─ web 中间件组
      ├─ EncryptCookies（cookie_consent 豁免解密）
      ├─ HandleInertiaRequests（注入共享 props）
      └─ PerformancePageCache（整页缓存：命中直接返回）
          └─ 路由分发
              ├─ 应用路由 routes/web.php
              │   ├─ CmsRoutes::register()  ← 最先注册，接管文章固定链接
              │   ├─ 登录/登出、首页、邮箱验证码
              │   └─ super_admin：备份下载、订单导出
              └─ 模块路由（插件系统在 boot 期自动加载）
                  └─ 控制器 → Inertia::render('Home' | 'CMS/ArticleShow' | 'Shop/Index' …)
                      └─ Vue 组件渲染
```

关键装配点在 `bootstrap/app.php`：

- `PerformancePageCache` 以 `append` 方式挂到 `web` 组末尾；
- `cookie_consent` Cookie 加入加密豁免（由 JS 写入，未加密）；
- 注册中间件别名 `author`；
- `/api/*` 或 JSON 请求统一渲染 JSON 异常。

### 5.2 插件（模块）生命周期

每个模块目录根部的 `plugin.php` 是清单，是插件信息的唯一事实来源：

```php
return [
    'id'           => 'quest',
    'name'         => 'Quest',
    'version'      => '1.0.0',
    'description'  => '签到与内容发布任务（货币奖励规则）',
    'author'       => 'CMSForum',
    'requires'     => ['mksine' => '^1.0'],
    'namespace'    => 'Modules\Quest',
    'plugin_class' => 'Modules\Quest\QuestPlugin',
    'autoload'     => ['Modules\Quest\\' => 'src/'],
    'hooks'        => ['public' => [], 'private' => []],
];
```

插件类实现 `Miran\Mksine\Core\Plugins\Contracts\PluginInterface`：

| 方法 | 触发时机 | 典型用途 |
| --- | --- | --- |
| `install()` | `mks-plugin:install` | 写入初始数据（**必须**用 `Schema::hasTable` 守卫，可能早于迁移执行） |
| `activate()` | `mks-plugin:activate` | 依赖自校验、一次性数据迁移（如改写 permalink 设置） |
| `deactivate()` | `mks-plugin:deactivate` | 注销运行时注册（**不删数据**） |
| `uninstall(bool $deleteData)` | `mks-plugin:uninstall` | 可选清理表与文件 |
| `boot()` | **每个请求**（已启用时） | 注册路由/视图/翻译/短码/事件监听/侧边栏类型/容器单例 |
| `migrationsPath()` `configPath()` `viewsPath()` `webRoutesPath()` `apiRoutesPath()` `translationsPath()` `filamentResourcesPath()` `filamentPagesPath()` `filamentWidgetsPath()` `namespace()` | — | 声明各类资源的磁盘位置，内核据此自动装配 |

状态持久化在 `mks_plugins` 表：`status`(installed/active/inactive)、`settings`、`installed_at`/`activated_at`/`deactivated_at`，以及启动守卫 `boot_failed` / `boot_error` / `boot_failed_at`（陈旧判定 TTL 见 `config/mksine.php` 的 `plugins.boot_guard_ttl`，默认 15 秒）。

**判定模块状态的辅助函数**（`app/Support/helpers.php`，已全局自动加载）：

```php
module_enabled('economy');    // 已安装且已启用
module_installed('economy');  // 仅判断已安装
```

两者在数据库未就绪（迁移期）时安全返回 `false`。

### 5.3 钩子系统

内核提供 `Miran\Mksine\Core\Hooks\Hooks`。当前项目主要使用其**短码注册**与**事件监听**能力：

- 短码：`Hooks::addShortcode($tag, $class, $priority, $catalog)`
- 事件：模块在 `boot()` 中 `Event::listen(...)`，把内核事件桥接成域事件

**事件桥接示例**：内核 `PostCreated` → `Modules\CMS\Listeners\BridgesArticlePublished` → 应用域事件 `App\Events\CmsArticlePublished`，`quest` 模块监听后者发放奖励。这样业务模块无需感知内核实现细节。

监听器发现（`php artisan mks:discover`）默认扫描内核 `Core/Listeners`，额外路径可在 `config/mksine.php` 的 `hooks.discovery_paths` 追加。慢钩子（> `slow_hook_threshold` ms，默认 100）会记录日志；`shouldQueue() === true` 的监听器走异步队列。

### 5.4 短码系统

在富文本内容（文章、单页、页面构建器）中支持 WordPress 式短码。解析限制见 `config/mksine.php`：`max_depth = 5`、`max_passes = 2`，解析结果可缓存（默认开启，TTL 3600 秒）。

| 短码 | 提供模块 | 作用 | 示例 |
| --- | --- | --- | --- |
| `[user field="name"]` | user | 输出用户资料字段 | `[user field="name"]` |
| `[wallet_balance currency="gold"]` | economy | 输出当前用户指定货币余额 | `[wallet_balance currency="gold"]` |
| `[checkin_status]` | quest | 渲染今日签到按钮/已签到标记 | `[checkin_status]` |
| `[coinpay_buy]` | crypto-pay | 文章加密货币购买按钮（付费文章自动生效） | `[coinpay_buy]` |

### 5.5 系统级侧边栏引擎

`app/Core/Sidebar/SidebarManager`（容器单例）是站点级能力，各模块在 `boot()` 中注册自己的**区域**与**卡片类型**。

```
registerArea('cms.sidebar', 'CMS 侧边栏', 'cms')
registerType(new CategoriesType())      ← 模块注册
        ↓
后台「侧边栏管理」创建卡片实例 → sidebar_cards 表
        ↓
SidebarManager::cardsFor('cms.sidebar')  ← 缓存 3600s
        ↓
前端 SidebarRenderer.vue 按 type 分发到对应 Vue 组件
```

**内置类型**（`AppServiceProvider` 注册）：`ImageLinkType`、`TextLinkType`、`HtmlType`

**模块注册的类型**：

| 类型 | 来源模块 | 前端组件 |
| --- | --- | --- |
| `CategoriesType` | cms | `sidebar/CategoriesCard.vue` |
| `LatestPostsType` | cms | `sidebar/LatestPostsCard.vue` |
| `CheckinType` | cms | `sidebar/CheckinCard.vue` |
| `UserCenterType` | cms | `sidebar/UserCenterCard.vue` |
| `AuthorCenterType` | cms | `sidebar/AuthorCenterCard.vue` |
| `DonationType` | cms | `sidebar/DonationCard.vue` |
| `AdSlotType` | ads | `sidebar/cards/ad_slot.vue` |

卡片类型需实现 `App\Core\Sidebar\CardTypeContract`：`typeKey()`、`label()`、`schema()`（Filament 动态表单字段）、`authorize($user)`（可选，控制谁能创建）。后台表单通过 `mergedTypeSchema()` 把所有类型的字段合并，再按所选类型 `visible()` 过滤。

### 5.6 设置系统

所有站点级配置统一落在 `settings` 表（`key` 唯一，`value` 字符串，最长 8192），后台通过继承 `MksSettingsPage` 的设置页编辑：

| 设置页 | 位置 | 关键键 |
| --- | --- | --- |
| `SiteSettingsPage` | 后台 → 站点设置 | SEO、注册白名单、Turnstile、GA、统计代码、广告平台验证、隐私/Cookie、邮件、队列、性能 |
| `DonationSettingsPage` | 后台 → 捐赠按钮 | `site_donation_url`、`site_donation_text` |
| `CmsPermalinkSettingsPage` | 后台 → CMS 固定链接 | `cms_posts_url`、`cms_single_post_url` |
| `CryptoPaySettingsPage` | 后台 → 加密支付 | `payment_channels`、`payment_fx_rate`、各通道凭据 |

读取方式：`App\Support\SiteSettings::get($key, $default)` / `::bool($key)` / `::seo()`，进程内静态缓存，`settings` 表未就绪时安全降级返回默认值。

**运行时配置覆盖**（`AppServiceProvider::boot()`）在每次请求把若干设置项反写到 Laravel config：

- GA：`analytics.property_id`、服务账号 JSON 落盘到 `storage/app/analytics/service-account-credentials.json`（内容 MD5 变化时才重写）；
- 缓存驱动：`performance_cache_store` 为 `redis` 或 `auto`（且 Redis 可达）时把 `cache.default` 切到 `redis`；
- 队列驱动：`queue_connection`（sync/database/redis）；
- 邮件：支持 `log` / `smtp` / `resend` 三种驱动，SMTP 主机/端口/账号/加密与发件人全部运行时注入。

### 5.7 前端渲染管线

`resources/js/app.ts` 中的页面解析规则：

| Inertia 页面名 | 解析到的文件 |
| --- | --- |
| `Home` | `resources/js/Pages/Home.vue` |
| `CMS/ArticleShow` | `modules/cms/resources/js/Pages/CMS/ArticleShow.vue` |
| `Shop/Index` | `modules/shop/resources/js/Pages/Shop/Index.vue` |

即：页面名首字母段小写后映射到 `modules/{module}/resources/js/Pages/{name}.vue`。

`HandleInertiaRequests` 共享给所有页面的 props：

| prop | 内容 |
| --- | --- |
| `auth` | 用户 id/name/email + `can_author`（是否具备创作权限） |
| `flash` | `success` / `error` 一次性消息 |
| `site` | 站点名 |
| `wallet` | 今日是否已签到 + 金币余额（economy + quest 均启用且有用户时才有值） |
| `menus` | 页眉 / 页脚菜单树 |

## 6. 业务模块详解

### 6.1 user — 用户中心

用户资料扩展与注册流程。

- **模型**：`UserProfile`（`user_profiles`：bio、website、signature、social_links、avatar_media_id、donation_url、donation_text）
- **后台**：`UserProfileResource`（导航标签 `UserProfiles`）
- **路由**：`GET /register`、`POST /register`、`GET /users/{id}`
- **能力**：
  - 邮箱验证码注册（`App\Support\EmailCode`，场景 `register` / `password`，60 秒限频，路由 `throttle:10,1`）
  - 邮箱域名白名单（`user_reg_whitelist_enabled` + `user_reg_whitelist_domains`）
  - 人机校验（Cloudflare Turnstile 优先，回退算术验证码，见 `App\Support\Captcha`）
  - 短码 `[user field="..."]`
- **页面**：`resources/views/auth/register.blade.php`、`users/show.blade.php`、`resources/js/Pages/User/ProfileShow.vue`
- **测试**：`RegistrationTest`、`RegistrationWhitelistTest`、`EmailCodeTest`

### 6.2 cms — 内容管理

前台内容展示的核心模块，接管了内核默认文章路由。

- **固定链接**：`CmsPermalink` 读取 `cms_posts_url`（默认 `/articles`）与 `cms_single_post_url`（默认 `/articles/{slug}`），后台可改。`CmsRoutes::register()` 必须由 `routes/web.php` **最先**调用——Laravel 按注册顺序匹配，先注册才能覆盖内核默认路由。
- **旧链接兼容**：结构变更后，旧 `/articles` 与 `/articles/{slugOrId}` 自动 301 到新结构。
- **模型**：`CmsBanner`（首页轮播图）、`SitePage`（单页）、`PostMeta`（文章扩展：view_count、extra JSON）、`Tag`
- **后台**：`CmsBannerResource`（首页轮播图）、`SitePageResource`（单页管理）、`CmsPermalinkSettingsPage`
- **路由**：
  - `GET /p/{slug}`、`/privacy`、`/terms`、`/about`（单页，由 `site_pages` 表维护）
  - `GET /search`（全文搜索）、`GET /feed`（RSS）、`GET /sitemap.xml`（缓存 1 小时）
  - `GET /c/{slug}`（分类归档页；**不能用 `/category/{slug}`**——内核 `FrontendResolver` 已占用该前缀且注册更早）
  - `GET|POST /comment/captcha`（游客评论验证码）
  - `/studio/*`（创作中心，中间件 `auth` + `author`）
- **创作中心**：`/studio/posts` 列表/新建/编辑/删除、`/studio/settings` 资料设置、`/studio/settings/security` 安全设置（含邮箱验证码）
- **侧边栏**：注册 `cms.sidebar` 区域与 6 种卡片类型
- **测试**：`AuthorCenterTest`、`CommentTest`

### 6.3 economy — 货币内核

虚拟货币账本，全站经济系统的结算底座。

- **模型**：
  - `EconomyCurrencyConfig`（`economy_currency_configs`）：货币定义与基准汇率，安装时写入默认三档 `gold` / `silver` / `copper`（1 / 0.1 / 0.01）
  - `Wallet`（`wallets`）：`user_id + currency` 唯一，余额 `decimal(18,6)`
  - `WalletLedger`（`wallet_ledger`）：借贷流水，**唯一索引 `(wallet_id, ref_type, ref_id, type)` 保证业务幂等**
- **服务**：`WalletService`
  - `apply()` 记账（带 `ref_type` / `ref_id`，重复提交被唯一索引拦截）
  - `transfer()` 用户间转账
  - `balance($user, $currency)` 查询余额
- **事件**：`WalletCredited`、`WalletDebited`
- **门面**：`Modules\Economy\Facades\Economy`
- **后台**：`WalletResource`（钱包）、`WalletLedgerResource`（钱包流水）、`CurrencyConfigResource`（货币配置）
- **短码**：`[wallet_balance currency="gold"]`
- **测试**：`WalletServiceTest`

### 6.4 quest — 签到与任务

- **模型**：`Quest`（`quests`）、`QuestCheckin`（`quest_checkins`，`user_id + checkin_date` 唯一）
- **默认任务**（安装时写入，后台可改奖励数额与货币）：

| key | 名称 | 奖励 | 每日上限 |
| --- | --- | --- | --- |
| `daily_checkin` | 每日签到 | 5 gold | 1 |
| `publish_article` | 发布文章 | 20 gold | 10 |
| `publish_topic` | 发帖 | 10 gold | 10 |

- **服务**：`CheckinService::checkin($user)`、`hasCheckedInToday($user)`
- **监听**：`RewardArticlePublish` 监听内核 `PostCreated`，发放发布奖励
- **路由**：`POST /quest/checkin`（需登录）
- **后台**：`QuestResource`（任务奖励）
- **短码**：`[checkin_status]`

### 6.5 crypto-pay — 加密支付

付费阅读 + 全站统一支付网关的宿主模块。

- **模型**：`CryptoOrder`（`crypto_orders`）、`CryptoPostPrice`（`crypto_post_prices`）
- **服务**：
  - `PaymentGateway`：统一入口，按用户所选 `method` 路由到已启用通道
  - 通道客户端：`CodePayClient`、`XunHuPayClient`、`PayPalClient`、`XcashClient`、`CoinPayService`
- **路由**：`POST /crypto-pay/checkout`、`GET|POST /crypto-pay/mock/{orderNo}`（Mock 收银台）、`POST /crypto-pay/webhook`（裸注册，无 CSRF，由 HMAC 验签认证）
- **后台**：`CryptoOrderResource`（加密支付订单）、`CryptoPaySettingsPage`
- **短码**：`[coinpay_buy]`
- **游客下单**：`crypto_orders.user_id` 可空，改用 `session_id` 绑定会话，并记录 `ip`、`guest_email` 用于审计

### 6.6 shop — 商品商城

- **模型**：`ShopProduct`（`shop_products`）、`ShopOrder`（`shop_orders`）
- **业务**：上架/下架/库存（`stock`）、累计销量（`sold`）、分类（`category`，可空）
- **发货方式** `delivery_type`：`none`（无） / `download`（下载链接） / `content`（直接给内容） / `invite_code`（发放邀请码），发货结果写入 `shop_orders.delivered_data`（JSON）
- **服务**：`ShopService::checkout()` / `markPaid()` / `deliver()`、`ShopService::mockMode()`
- **路由**：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/shop` | 商城首页 |
| GET | `/shop/{slug}` | 商品详情 |
| POST | `/shop/buy` | 下单（需登录） |
| GET | `/shop/orders` | 我的订单（需登录） |
| GET|POST | `/shop/mock/{orderNo}` | Mock 收银台 |
| GET | `/shop/paypal/return` | PayPal 同步返回 |
| POST | `/shop/webhook` | Xcash 回调（裸注册，无 CSRF） |
| GET|POST | `/shop/notify`、`/shop/notify/return` | 码支付 / 虎皮椒通知与同步返回 |

- **后台**：`ShopProductResource`（商品）、`ShopOrderResource`（订单）；后台首页挂 `ShopStatsWidget` 统计挂件
- **开关**：`shop_enabled`

### 6.7 invite — 邀请码

- **模型**：`InviteCode`（`invite_codes`）、`InviteOrder`（`invite_orders`）
- **来源** `source`：`admin`（管理员生成）/ `gold`（金币购买）/ `crypto`（加密支付购买）
- **服务**：`InviteService`

  - `validateForRegistration($code)` / `consume($code, $userId)` 注册校验与核销

- **路由**：`/invite/*`（需登录）：中心页、金币购买、加密购买、Mock 收银台；回调 `/invite/webhook`、`/invite/notify`、`/invite/paypal/return`（均裸注册，无 CSRF）

- **后台**：`InviteCodeResource`

- **前端**：`resources/js/Components/ads/`

## 9. 权限与角色

### 9.1 角色

| 角色 | 权限 |
| --- | --- |
| `super_admin` | **绕过全部授权检查**（`Gate::before` 直接返回 `true`）；可访问 Horizon、备份下载、订单导出、站点设置、插件打包 |
| `author` | 进入创作中心 `/studio/*`（`author` 中间件）；撰写与管理自己的文章 |
| 其他角色 | 由 Filament Shield 生成的权限策略控制 |

### 9.2 实现要点

- `AppServiceProvider::boot()` 注册 `Gate::before`：`super_admin` 一律放行。
- `Gate::define('viewHorizon')`：仅 `super_admin`。
- `App\Support\Author::AUTHOR_ROLES = ['author', 'super_admin']`，前台 UI（`auth.can_author`）与服务端中间件共用同一判定；角色表未就绪时静默视为无权限。
- `App\Http\Middleware\AuthorMiddleware`：未登录跳转登录页，已登录但无作者角色 → 403。
- Filament Shield（v4.3.1）为后台资源生成权限；`config/filament-shield.php` 可调整。
- `app/Policies/` 下有 10 个策略：Post、Category、Comment、Media、Menu、MenuLocation、Page、GeoState、Role、User。

### 9.3 注册安全

多层校验叠加：

1. Cloudflare Turnstile（开启时）或算术验证码回退 —— `App\Support\Captcha`
2. 邮箱验证码（60 秒限频，路由 `throttle:10,1`）—— `App\Support\EmailCode`
3. 邮箱域名白名单（`user_reg_whitelist_*`）—— 防临时邮箱灌水
4. 邀请码（开启 `invite_registration_enabled` 时强制核销）

| `xunhupay` | 支付宝（alipay）、微信（wechat） | `XunHuPayClient` |
| `paypal` | PayPal | `PayPalClient` |
| `xcash` | 加密货币（crypto） | `XcashClient` |
| `mock` | Mock 支付（本地联调） | — |
| `coinpayments` | 加密货币 | `CoinPayService` |

- 启用通道在后台设置 `payment_channels`（支持逗号分隔或 JSON 数组两种格式）。
- **Mock 模式优先级最高**：`crypto_pay_mock_mode` 开启时 `enabledChannels()` 直接返回 `['mock']`，便于本地联调。
- CNY 通道（码支付 / 虎皮椒）金额按 `payment_fx_rate`（USD→CNY）换算。
- 用户可自选支付方式，网关按 `method` 路由到支持该方式的首个已启用通道；未指定则用第一个可用通道。

### 10.3 回调与入账

1. 第三方回调到达裸注册路由（无 CSRF）；
2. 各客户端自行验签（HMAC / 签名）；
3. 校验通过后调用对应服务的 `markOrderPaid()`（shop / invite）或订单状态更新（crypto-pay）；
4. 幂等保障：shop/invite 依赖订单状态判断，economy 依赖 `wallet_ledger` 唯一索引。

### 10.4 联调建议

本地开发开启 `crypto_pay_mock_mode`，走 `/shop/mock/{orderNo}`、`/crypto-pay/mock/{orderNo}`、`/invite/mock/{orderNo}` 三个 Mock 收银台（GET 查看、POST 确认支付）。

## 11. 性能与缓存

### 11.1 整页缓存（`PerformancePageCache`）

仿 WP Super Cache 的自研引擎，挂在 `web` 中间件组末尾。

**缓存条件（全部满足）**：

1. 后台开关 `performance_page_cache_enabled` 已开启；
2. 请求方法可缓存（GET/HEAD），且非 ajax / pjax；
3. **未登录用户**（登录用户永远实时渲染）；
4. 无 `X-Inertia` 头（Inertia 部分刷新/JSON 不与 HTML 页共用缓存）；
5. 查询串无 `nocache`（手动绕过）；
6. 路径不在排除列表中。

**排除前缀**：`admin`、`login`、`logout`、`register`、`studio`、`invite`、`horizon`、`email`、`comment/captcha`、`crypto-pay`、`livewire`、`octane`、`sitemap.xml`、`up`、`user`、`quest`、`api`、`privacy`。首页（空路径）参与缓存。

**存储与 TTL**：键为 `pcache:` + `sha256(GET|scheme://host/uri)`，值快照 `{body, status, headers}`。TTL 取 `performance_page_cache_ttl`（默认 3600，最小 60 秒）。存储由 `performance_cache_store` 决定：`redis` / `file` / `auto`（Redis 可达时自动用 Redis）。

**索引与清理**：活跃缓存键记录在 `pcache:index`（上限 2000 条，保留 7 天），后台「清空缓存」按钮调用 `clearAll()` 精确清除。

**命中统计**：每次请求写入 `performance_stats`（hits / misses / total_ms），是后台性能仪表盘图表的数据源。

### 11.2 其他性能设施

| 设施 | 说明 |
| --- | --- |
| Redis | 缓存/队列驱动；`auto` 模式下由 `SystemProbe::redisAvailable()` 探测后自动切换 |
| OPcache | `SystemProbe::opcache()` 查看状态，支持后台 `opcacheReset()` |
| Laravel Octane | v2.19.1 已安装，`SystemProbe::octane()` 探测；注意常驻内存下静态缓存（如 `SiteSettings::$cache`）的失效策略 |
| Laravel Horizon | v5.48.3，队列面板，仅 `super_admin` 可见 |
| spatie/laravel-responsecache | v8.4.3 已引入 |
| 短码解析缓存 | `mksine.shortcodes.cache`，默认开启 TTL 3600 |
| 侧边栏卡片缓存 | `sidebar.cards.{area}`，TTL 3600，保存卡片后 `Cache::flush()` |

## 15. 二次开发指南

### 15.1 新增一个模块

```bash
# 1. 脚手架（内核提供）
php artisan mks-plugin:make my-feature

# 2. 补齐目录
mkdir -p modules/my-feature/{src/{Models,Services,Http/Controllers,Sidebar},database/migrations,routes,resources/{js/Pages,lang/{en,zh_CN}},tests}
```

最小可用结构：

```
modules/my-feature/
├── plugin.php                  # 清单：id / namespace / plugin_class / autoload
├── src/MyFeaturePlugin.php     # 实现 PluginInterface
├── database/migrations/
└── routes/web.php
```

`MyFeaturePlugin` 必须实现的要点：

```php
class MyFeaturePlugin implements PluginInterface
{
    public function id(): string { return 'my-feature'; }

    public function install(): void {
        // ★ 必须先用 Schema::hasTable 守卫——install 可能早于迁移执行
        if (! Schema::hasTable('my_table')) { return; }
        // 写入初始数据
    }

    public function activate(): void {
        // 依赖自校验（约定：依赖缺失直接抛 RuntimeException）
        foreach (['user'] as $required) {
            if (! module_enabled($required)) {
                throw new \RuntimeException("模块 my-feature 依赖 {$required}，请先安装并启用。");
            }
        }
    }

    public function boot(): void {
        // 每请求执行：注册视图/翻译/短码/事件/侧边栏类型/容器单例
        view()->addNamespace('my-feature', $this->viewsPath());
    }

    // migrationsPath() / webRoutesPath() / filamentResourcesPath() …
}
```

### 15.2 约定

1. **路由注册顺序敏感**：需要覆盖内核路由时（如 CMS 固定链接），必须在 `routes/web.php` 最早期注册。
2. **支付回调必须裸注册**：在插件 `boot()` 中用 `Route::post(...)` 直接注册（不在 `web` 组内，无 CSRF），安全性由各自验签保证。
3. **侧边栏扩展**：模块在 `boot()` 调 `Sidebar::registerArea()` 注册区域、`Sidebar::registerType()` 注册卡片类型；卡片类型实现 `CardTypeContract`，`schema()` 返回 Filament 字段，`authorize()` 控制可见性。
4. **翻译命名空间**：需在面板构建前注册（`AppServiceProvider` 中维护模块列表）。
5. **设置项**：新增设置走继承 `MksSettingsPage` 的设置页 + `SiteSettings` 读取；需要在 Laravel config 层生效的，在 `AppServiceProvider::boot()` 里反写。
6. **短码**：在 `boot()` 中 `Hooks::addShortcode()`，必须附带 `ShortcodeCatalogEntry`（后台短码目录展示用）。
7. **Inertia 页面命名**：页面名首段小写 = 模块目录名，如 `Shop/Index` → `modules/shop/resources/js/Pages/Shop/Index.vue`。
8. **测试**：模块测试继承 `Modules\Tests\ModuleTestCase`，覆写 `$activeModules` 与 `$truncateTables`。

### 15.3 富文本扩展

新增 CKEditor 语言/方向需求时配置 `mksine.ckeditor.ui_language` / `content_language`（例如面板英文但正文波斯语 → `content_language=fa`）。评论目标类型在 `mksine.commentable_types` 中登记，模块可在 `boot()` 合并自定义模型。

## 16. 约定与已知坑

### 16.1 必须注意的坑

| 坑 | 说明与规避 |
| --- | --- |
| **模块测试用 MySQL** | `phpunit.xml` 硬编码 `DB_CONNECTION=mysql`、`DB_DATABASE=cmsforum_test`，而 `.env.example` 默认 sqlite。跑模块测试前需准备 MySQL 库。 |
| **不能用 `RefreshDatabase`** | `ModuleTestCase` 明确注释：Laravel 13 + MySQL 8.4 下外层事务与 `WalletService` 内层 `DB::transaction` 的嵌套 SAVEPOINT 冲突。改为「结构只建一次 + 每测试 truncate 业务表」。 |
| **`/category/{slug}` 已被占用** | 内核 `FrontendResolver` 先注册该前缀，分类归档页只能用 `/c/{slug}`。 |
| **`/author/{id}` 已被占用** | 创作中心必须用 `/studio` 前缀，否则 `/author/posts` 会被作者主页路由抢走。 |
| **CMS 路由必须最先注册** | `CmsRoutes::register()` 若晚于内核路由注册，固定链接设置将不生效。 |
| **`install()` 可能早于迁移** | 所有 `install()` 里的数据写入必须用 `Schema::hasTable()` 守卫。 |
| **Octane 下的静态缓存** | `SiteSettings::$cache` 是进程内静态属性，常驻内存时需留意失效时机（必要时调 `SiteSettings::flush()`）。 |
| **`sidebarCards` 缓存清理粗暴** | `SidebarManager::flushCache()` 直接 `Cache::flush()`（清整个缓存），不要在高流量路径调用。 |
| **PHP 上传限制** | `MKS_CMS_MAX_UPLOAD_MB` 必须 ≤ PHP 的 `upload_max_filesize` 与 `post_max_size`。 |
| **ZIP 更新不装依赖** | 生产机无 composer/npm，ZIP 必须预构建且不得引入新 Composer 依赖。 |
| **页面缓存与登录态** | 登录用户、Inertia 请求、ajax/pjax 一律不缓存；若前台出现"看到别人的页面"，先确认是否被 `pcache` 命中（加 `?nocache=1` 验证）。 |

### 16.2 命名约定

- 模块目录：短横线（`crypto-pay`）→ 命名空间：大驼峰（`Modules\CryptoPay`）
- 插件类：`<Module>Plugin`，实现 `PluginInterface`
- Filament 资源目录：`src/Filament/Resources/<Name>Resource/`，内含 `Pages/`、`Schemas/`、`Tables/` 三个子目录（Form/Table 拆分为独立类）

- DOM 事件与参考文档：源码注释中出现的 `§九十八`、`ADR-010` 等编号指向 `docs/` 下的设计文档
